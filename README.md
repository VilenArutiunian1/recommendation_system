# Рекомендательная система постов

Сервис, который по пользователю и моменту времени возвращает top-k постов для ленты. Модель — CatBoost-классификатор, предсказывающий вероятность лайка после просмотра; признаки — данные пользователя, тема поста и сглаженные CTR-счётчики. Сервис написан на FastAPI, данные берутся из PostgreSQL.

## Структура

| Файл | Что внутри |

| [recommender.py](recommender.py) | `Recommender`: сборка признаков для пользователя из БД, скоринг, фолбэк на популярное |

| [database.py](database.py) | Подключение к Postgres и потоковая загрузка таблиц |
| [schema.py](schema.py) | Pydantic-схемы таблиц |

## Данные

Три таблицы в схеме `public`:

- `user` — `id, gender, age, country, city, exp_group, os, source`
- `post` — `id, text, topic`
- `feed_action` — `user_id, post_id, action ('view' | 'like'), time` (~65 млн строк)

## Признаки

Каждый пример обучающей выборки — просмотр; `target = 1`, если пользователь когда-либо лайкнул этот пост.

- **Категориальные:** `user_gender`, `user_country`, `user_city`, `user_exp_group`, `post_topic`
- **Числовые:** `user_age`, `hour`, `weekday`, `user_topic_views`, `topic_ctr`, `post_ctr`, `user_topic_ctr`, `user_ctr`

Счётчики просмотров и лайков считаются кумулятивно по времени, только по событиям *до* текущего (без утечки будущего). CTR сглаживается к априорному значению:

```
ctr = (likes + smooth * prior) / (views + smooth)
```

Иерархия априорных значений: глобальный CTR → `topic_ctr` → `post_ctr`, и `topic_ctr` → `user_topic_ctr`. Для `user_ctr` prior — средний CTR пользователя. Коэффициенты сглаживания заданы в [ctr.py](ctr.py).

## Обучение

Обучение идёт на последних 5 млн просмотров; счётчики при этом считаются по всей истории. Валидация — разбиение по времени: последние 20% просмотров идут в тест.

Метрики (`validate_classifier`):

| | ROC AUC | Group AUC (по пользователям) |
|---|---|---|
| train | 0.7049 | 0.6824 |
| test | 0.6803 | 0.6621 |

Group AUC — AUC внутри каждого пользователя, усреднённый с весом по числу его примеров; он ближе к задаче ранжирования ленты, чем общий ROC AUC.

Финальная модель обучается на всех данных и сохраняется в `model.cbm`:

```python
from database import load_tables, postgres_engine
from model import train_final_classifier

users, posts, feed = load_tables(postgres_engine())
train_final_classifier(users, posts, feed)
```

Загрузка лога и обучение требуют заметного объёма памяти и занимают около 10 минут (см. [model.ipynb](model.ipynb)).

## Запуск сервиса

1. Установить зависимости:

   ```bash
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. Создать `.env` с доступом к базе:

   ```
   DB_USER=...
   DB_PASSWORD=...
   DB_HOST=...
   DB_PORT=5432
   DB_NAME=...
   ```

3. Положить обученную модель в `model.cbm` (файл не хранится в git) или указать путь через переменную `MODEL_PATH`.

4. Запустить:

   ```bash
   uvicorn app:app --host 0.0.0.0 --port 8000
   ```

При старте сервис загружает модель, статистику по всем постам и тексты постов; после строки `Service is ready` в логе он готов принимать запросы.

## API

### `GET /health`

```json
{"status": "ok"}
```

### `GET /post/recommendations/`

| Параметр | Тип | Описание |
|---|---|---|
| `id` | int | ID пользователя |
| `time` | datetime | Момент запроса (используются час и день недели) |
| `limit` | int, 1–100 | Число постов, по умолчанию 10 |

```bash
curl 'http://localhost:8000/post/recommendations/?id=200&time=2021-12-01T12:00:00&limit=5'
```

Ответ — список постов:

```json
[
  {"id": 1234, "text": "...", "topic": "movie"}
]
```

### Как формируется выдача

1. Для пользователя из БД собираются его профиль и счётчики по темам; они объединяются со статистикой всех постов-кандидатов.
2. Посты, с которыми пользователь уже взаимодействовал, исключаются.
3. Модель скорит оставшиеся посты, возвращаются top-`limit` по вероятности лайка.
4. Если пользователя нет в базе или непросмотренных постов не осталось, отдаются самые популярные посты по сглаженному `post_ctr`.

Статистика постов загружается один раз при старте, поэтому новые лайки и просмотры попадают в CTR постов только после перезапуска сервиса. Счётчики самого пользователя читаются из БД на каждый запрос.
